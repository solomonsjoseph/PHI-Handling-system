# PHI Threat Model

**Version:** 2026-07-06.task7
**Status:** Implemented threat-model documentation; clinician, counsel, and external review statuses remain PENDING unless separately attested.

This threat model covers the evidence-first PHI corpus, benchmark, validation, release-evidence, and PHI/LLM runtime-safety harness. It is a security and trust artifact, not a regulatory certification.

## System boundary

In scope:

- Synthetic corpus generation and manifests under `harness.generate_corpus` and `corpus/MANIFEST.json`.
- Standalone structural validation through `harness.run_all_validations`.
- Release evidence hashing and claim-level derivation through `harness.release_evidence`.
- PHI/LLM read-path and output controls in `phi_engine.security.llm_tool_guard`.
- Source-tree and promotion checks in `phi_engine.security.llm_source_gate` and `phi_engine.security.phi_guard_gate`.
- Audit-zone and snapshot-root read barriers in `phi_engine.audit.zone_guards`.
- PHI LLM client selection and external-provider approval controls in `phi_engine.config.config.get_llm_client`.
- Benchmark artifacts generated by local benchmark adapters.

Out of scope:

- Real PHI ingestion or storage. No real PHI may be committed to this repository.
- Claims that generated synthetic data satisfies any institution's regulatory, IRB, legal, or clinical review obligations.
- External clinician review, counsel review, cloud-provider review, or independent third-party validation unless separately documented as complete.
- Production encryption/RBAC guarantees beyond the explicit configuration gates and tests present in the repository.

## Assets

Primary assets:

- Synthetic corpus records and span-level gold annotations.
- Corpus manifests, SHA-256 file hashes, validation reports, MIA smoke reports, and release evidence hashes.
- Benchmark summaries and raw prediction artifacts that intentionally exclude raw record text.
- Authority citations and jurisdiction metadata.
- PHI/LLM safety configuration, approval state, and guard behavior.
- Audit, snapshot, quarantine, and release directories that could become sensitive if misused.

Security properties to preserve:

- No real PHI in source, corpus, tests, benchmark artifacts, validation reports, or release evidence.
- No unapproved external egress for PHI-task LLM calls.
- Deterministic, reproducible evidence artifacts tied to manifests and hashes.
- Value-free error messages for PHI/security blocking paths.
- Honest claim levels based on implemented, tested, manifested, and reviewed capabilities.

## Trust boundaries

| Boundary | Trusted side | Untrusted or lower-trust side | Controls |
|---|---|---|---|
| Source tree to LLM-visible tool input | Repository code and approved generated artifacts | Any path requested by an LLM tool | `phi_engine.security.llm_tool_guard.validate_llm_read_path`, `phi_engine.audit.zone_guards.deny_if_audit_zone`, `phi_engine.audit.zone_guards.deny_if_snapshot_root` |
| Tool result to LLM output | Value-free, PHI-screened result payload | Any returned string, mapping, sequence, dataclass, or primitive | `phi_engine.security.llm_tool_guard.guard_llm_output` |
| Generated corpus to release claim | Corpus JSONL plus manifest | Public claim text, release evidence, benchmark conclusions | `harness.run_all_validations`, `harness.release_evidence` |
| Candidate artifacts to promoted output | Generated artifacts under review | Release folders, evidence packets, user-visible reports | `phi_engine.security.phi_guard_gate.run_phi_guard_gate`, `phi_engine.security.llm_source_gate.scan_tree_for_phi` |
| Local PHI workflow to external provider | Disabled or approved LLM provider configuration | External LLM APIs and network egress | `phi_engine.config.config.get_llm_client` |
| Audit/snapshot stores to readers | Guarded internal evidence and operational stores | General file reads and LLM-mediated reads | `phi_engine.audit.zone_guards.deny_if_audit_zone`, `phi_engine.audit.zone_guards.deny_if_snapshot_root` |

## Data flows

1. Corpus generation writes synthetic JSONL records and `corpus/MANIFEST.json` with per-file SHA-256 hashes, span-error status, validation status, claim level, and registry hash.
2. Validation runs with `harness.run_all_validations`, producing `validation_report.json` from the offset, hash, taxonomy, citation, jurisdiction, format-parse, and static no-real-PHI validators.
3. Benchmark adapters read corpus records, produce summaries and raw prediction artifacts, and must not write raw record text to raw prediction artifacts.
4. MIA smoke testing reads generated corpus records, emits aggregate attack evidence, and must not write raw text.
5. Release evidence is assembled by `harness.release_evidence`, hashing the manifest, validation report, optional MIA report, and planned-capability limitations.
6. LLM-visible tool reads first pass through `phi_engine.security.llm_tool_guard.validate_llm_read_path`, which applies audit-zone, snapshot-root, and clean-zone checks before returning a resolved path.
7. LLM-visible tool outputs pass through `phi_engine.security.llm_tool_guard.guard_llm_output`, which scans serialized output through the PHI gate before returning values to an LLM.
8. Promotion or source-tree safety checks use `phi_engine.security.phi_guard_gate.run_phi_guard_gate` and `phi_engine.security.llm_source_gate.scan_tree_for_phi` to detect residual PHI risks before artifacts become trusted evidence.
9. PHI LLM client creation uses `phi_engine.config.config.get_llm_client`, with external providers disabled by default unless explicitly approved by environment/configuration controls.

## STRIDE controls

| STRIDE category | Threat | Required control evidence | Residual risk |
|---|---|---|---|
| Spoofing | A tool or artifact pretends to be approved release evidence. | Release packets are built with `harness.release_evidence` and include hashes of the manifest and validation report. | Hashes prove artifact identity, not institutional approval. |
| Tampering | Corpus files change after manifest creation. | `harness.run_all_validations` includes `hash_validator`, which recomputes manifest file hashes. | Manifest itself must be distributed and reviewed with release evidence. |
| Repudiation | A release claim cannot be tied to validation evidence. | `harness.release_evidence` records manifest/report hashes and claim level. | Human signoff is PENDING until clinician/counsel review artifacts are completed. |
| Information disclosure | Real PHI or sensitive paths reach an LLM or public artifact. | `phi_engine.security.llm_tool_guard.validate_llm_read_path`, `phi_engine.security.llm_tool_guard.guard_llm_output`, `phi_engine.security.phi_guard_gate.run_phi_guard_gate`, and `phi_engine.security.llm_source_gate.scan_tree_for_phi`. | Static and rule-based scanning reduces risk but is not a proof that arbitrary future content is PHI-free. |
| Denial of service | Large validation, benchmark, or LLM operations exhaust resources. | Release commands are explicit and reproducible; external LLM providers are disabled by default. | Dedicated resource limits are not a substitute for operational deployment controls. |
| Elevation of privilege | LLM tools read audit/snapshot roots or call external providers without approval. | `phi_engine.audit.zone_guards.deny_if_audit_zone`, `phi_engine.audit.zone_guards.deny_if_snapshot_root`, `phi_engine.security.llm_tool_guard.validate_llm_read_path`, and `phi_engine.config.config.get_llm_client`. | Production RBAC/encryption are not claimed complete. |

## Release gates

A release MUST NOT claim L4 or L5 status unless all of the following are true and evidenced in durable artifacts:

- Validators pass through `harness.run_all_validations` for the release corpus and manifest.
- Strict benchmark artifacts exist, including a strict stock Presidio summary and raw prediction artifact that excludes raw text.
- Threat-model controls pass their tests, including PHI/LLM safety tests for path denial, output blocking, and disabled external providers.
- Clinician review status and counsel review status are recorded; if no review is complete, both statuses must remain `PENDING`.
- External provider egress is explicitly approved before any PHI-task external LLM provider is used.
- `harness.release_evidence` records manifest, validation report, optional MIA smoke report, limitations, and claim level.

L4/L5 claims are not supported by this repository until clinician/counsel review and external validation evidence are completed and recorded.

## Residual risks

- Structural validation is evidence of corpus integrity, not regulatory certification.
- The static no-real-PHI validator is a guardrail, not a mathematical proof that no real PHI exists.
- Clinician review is PENDING; no clinical plausibility signoff has been completed in this repository.
- Counsel review is PENDING; authority citations and legal-basis analysis are not legal advice.
- External cloud benchmark and LLM provider review is PENDING unless a project-specific approval artifact is added.
- Production encryption and RBAC are not claimed complete by this threat model.
- Benchmark results on synthetic corpora may not predict performance on real clinical distributions.
- MIA smoke evidence is deterministic release evidence only; it does not prove non-inferability against stronger adversaries.
